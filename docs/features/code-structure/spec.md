# 코드 구조 정리

확인: 2026-11-14

## 목표

명령과 영역이 늘어도 한 파일에 타입·구현·변환이 쌓이지 않고, 새 기여자가 영역 하나를 고칠 때 찾을 곳이 정해져 있다.
공개 API 클라이언트와 웹 클라이언트를 영역 인터페이스로 구분해 쓴다. 사용자에게 보이는 동작은 바뀌지 않는다.

## 배경

- `src/api/client.ts` 1328줄·메서드 65개, `src/api/types.ts` 995줄·타입 157개다. [ADR-017](../../adr/superseded/017-api-types-single-file.md) 의 재검토 조건(800줄, 새 영역)을 둘 다 넘었다.
- 웹 로그인 세션 기능이 영역 인터페이스(`api/<영역>/types.ts`)와 웹 구현(`api/<영역>/web.ts`)을 먼저 들였다. 공개 구현은 아직 `client.ts` 한 파일이다.
- `utils/` 30개에 영역을 모르는 공통 부품, post·wiki 본문 규칙, 메일 전용 코드가 섞여 있고 일부가 상위 계층을 import 한다.
- 명령 파일 일부(`stream/list.ts`, `messenger/channels.ts` 등)에 도메인 로직이 들어 있고, 명령 나무 조립 자리가 영역마다 다르다.

## 범위

- api 계층 안을 영역별로 나눈다: 타입, 공개 구현, 웹 구현, 영역 인터페이스.
- `body/` 를 새로 두고 `utils/` 는 영역을 모르는 공통 부품만 남긴다.
- 명령 파일의 도메인 로직을 같은 영역의 다른 파일로 빼고, 모든 영역이 자기 명령 나무를 내보낸다.
- 계층·영역 의존 규칙을 검사하는 테스트를 두고 CI 에서 실패로 막는다.
- import 경로 별칭 `@/…` 를 도입한다.
- 옛 문서와 ADR 본문의 `src/…` 경로를 새 경로로 고친다.
- `config/store.ts`, `skill/manager.ts` 분할은 선택 항목으로 마지막에 둔다.

PR 순서와 단위(동작을 바꾸지 않는 PR 여럿):

1. R0 구조 ADR, 의존 규칙 테스트(허용 목록으로 시작), CLI 도움말 스냅숏 스크립트, 경로 별칭 도입
2. R1 타입 분할
3. R2 공개 클라이언트 분할
4. R3 utils 재분류와 `body/`
5. R4 명령 파일 로직 분리와 영역별 명령 나무
6. R5(선택) `config/store.ts`, `skill/manager.ts` 분할

범위 밖:

- 영역별 세로 폴더(`domains/<영역>/`)로 계층 폴더 전체를 바꾸는 구조.
- 사용자에게 보이는 명령·옵션·출력·종료 코드의 변경.
- 새 기능.

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 사용자에게 보이는 동작이 바뀌지 않는다 | PR 마다 전후의 모든 명령 `--help` 스냅숏이 같고, `pnpm test` 의 테스트 수가 줄지 않으며 모두 통과한다 |
| REQ2 | 공개 API 호출이 바뀌지 않는다 | R2 전후의 `pnpm api:inventory` 출력이 같다 |
| REQ3 | api 계층은 영역마다 타입·공개 구현·웹 구현이 한 폴더에 있다 | `src/api/<영역>/` 에 `types.ts`, `public.ts`, `web.ts` 가 있고, `client.ts`·`types.ts` 는 재내보내기만 남는다 |
| REQ4 | 공개 구현과 웹 구현은 영역 인터페이스로 구분된다 | 소비자(resolver·services·명령)가 필요한 영역 인터페이스만 받고, 두 구현이 그 인터페이스를 컴파일러 검사로 구현한다. 공개 구현과 웹 구현은 서로 import 하지 않는다 |
| REQ5 | 계층·영역 의존 규칙을 어기면 CI 가 실패한다 | 규칙 테스트가 위반 import 를 실패로 내고, 정리 PR 마다 허용 목록이 줄어 R4 뒤에는 비어 있다 |
| REQ6 | import 경로 별칭 `@/…` 를 쓸 수 있다 | 빌드·타입 검사·vitest(`vi.mock` 포함)가 별칭을 풀고, 새 코드와 옮긴 코드가 별칭을 쓴다 |
| REQ7 | 문서의 코드 경로가 실제 경로와 맞는다 | 옛 문서와 ADR 본문의 `src/…` 경로가 모두 존재하는 파일을 가리킨다(검사 스크립트로 확인) |
| REQ8 | 파일 이동의 이력이 남는다 | 이동 커밋과 내용 수정 커밋이 나뉘어 `git log --follow` 가 옮긴 파일의 이전 이력을 찾는다 |
