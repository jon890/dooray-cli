# zsh 특수 배열 `path`를 loop 변수로 사용

## 관찰

공개 문서 세 곳의 동일 문구를 검사하는 loop가 첫 파일을 처리한 뒤 `rg: command not found`로 실패했다.

## 원인

zsh에서 `path`는 `PATH`와 연동된 특수 배열인데 일반 loop 변수로 사용했다.
첫 대입이 명령 검색 경로를 덮어써 이후 명령을 찾지 못했다.

## 영향

Phase 02 완료 전 품질 검증이 중단됐고 task 상태는 `pending`으로 유지됐다.
코드와 문서 변경 내용에는 영향이 없었다.

## 대응

loop 변수를 `doc_file`로 바꾸고 품질 검증 묶음을 처음부터 다시 실행했다.

## 검증

세 공개 문서에 대해 `rg -q -F '기존 제목·본문·태그'`가 순서대로 실행되고 후속 명령도 정상 실행되는지 확인했다.

## 배운 점

셸 스크립트의 지역 변수도 `path`처럼 shell 상태와 연결된 이름을 피해야 한다.
전역 운영 규칙의 시스템 변수 이름 재사용 금지를 task 검증 명령에도 적용한다.

## 후속

기존 전역 운영 규칙이 같은 위험을 이미 다루므로 별도 규칙으로 승격하지 않는다.
