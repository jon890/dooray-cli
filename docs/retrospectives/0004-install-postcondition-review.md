# 설치 후 상태를 성공으로 가정한 검증 누락

## 관찰

독립 코드 검토에서 패키지의 스킬 원본이 없을 때도 심볼릭 링크 생성 자체는 성공해 명령이 설치 완료 문구를 출력할 수 있다는 지적을 받았다.

## 원인

배포 검증이 원본 파일 존재를 보장한다고 가정했고, 런타임 설치 함수에서 원본 사전 조건과 설치 후 `current` 상태를 별도로 강제하지 않았다.

## 영향

불완전한 패키지나 잘못 계산된 패키지 루트에서는 깨진 링크로 전환한 뒤 성공처럼 보일 수 있었다.

## 대응

원본 디렉터리와 필수 스킬 파일을 활성 링크 변경 전에 검사하고, 전환 후 상태가 `current`인지 강제하도록 수정했다.

## 검증

원본이 없는 context에서 기존 활성 링크가 유지되고 종료 코드 1 오류가 발생하는 회귀 테스트를 추가했다.
스킬 관리자 16개 테스트와 전체 225개 테스트, 타입 검사, 빌드, 패키지 검증이 통과했다.

## 배운 점

배포 단계의 자산 검증과 런타임 작업의 사전·사후 조건은 서로 대체할 수 없다.

## 후속

런타임 사전·사후 조건을 코드와 회귀 테스트로 고정했으므로 별도 공용 지침으로 승격하지 않는다.
