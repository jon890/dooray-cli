# 관리 저장소 경계의 1단계 검토 누락

## 관찰

1단계 독립 코드 검토에서 `references` 루트 심볼릭 링크 추적, 느슨한 `installedAt` 검증, 사라진 관리 저장소 링크의 비관리 오분류를 발견했다.

## 원인

내부 파일 심볼릭 링크와 잘못된 manifest 필드는 테스트했지만 수집 시작 디렉터리 자체의 링크와 날짜 형식까지 경계를 확장하지 않았다.
깨진 링크 판정도 레거시 npm 경로 규칙만 재사용해 새 관리 저장소 루트를 포함하지 않았다.

## 영향

외부 디렉터리 파일이 해시에 포함될 수 있고, 잘못된 설치 시각을 가진 manifest가 유효해질 수 있으며, 사라진 관리 저장소 링크가 기본 복구되지 않을 수 있었다.

## 대응

수집 루트 `lstat`, 엄격한 UTC ISO 시각 검증, 관리 저장소 루트의 깨진 링크 판정을 추가하고 각각 회귀 테스트로 고정했다.
`dataRoot` 기본 경로와 활성 링크 rollback의 rename 순서도 함께 검증했다.

## 검증

매니페스트·관리자 대상 31개 테스트와 타입 검사, 독립 재검토 `APPROVED`가 통과했다.

## 배운 점

재귀 수집의 symlink 정책은 내부 entry뿐 아니라 시작 경로 자체에도 적용해야 하며, 새 저장 경계를 추가하면 기존 broken 판정의 관리 주체 규칙도 함께 확장해야 한다.
