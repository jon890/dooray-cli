# 팀원이 worktree 가 아닌 저장소 루트를 보고 파일이 안 바뀌었다고 판정했다

## 관찰

계획 수정 후 재평가를 요청했더니 팀원이 파일 넷의 md5 가 그대로이고 `git status` 가 깨끗하다며 직전과 같은 판정을 냈다.
실제로는 세 파일이 수정 상태였고 md5 도 달랐다.

## 원인

팀원이 `/Users/nhn/personal/dooray-cli` 를 읽었을 가능성이 크다.
그 경로는 main 브랜치를 checkout 한 상태라 plan 브랜치의 수정이 보이지 않고 `git status` 도 깨끗하게 나온다.
스폰 프롬프트에 worktree 절대경로를 주었지만 재평가 요청 메시지에는 다시 적지 않았다.

## 영향

같은 판정을 한 번 더 받아 재평가 왕복이 한 차례 늘었다.

## 대응

`git status --porcelain` 출력과 세 파일의 md5, 바뀐 실제 라인을 `grep` 으로 떠서 증거로 붙이고 재요청했다.
읽을 경로가 반드시 worktree 절대경로로 시작해야 한다는 것도 함께 적었다.
팀원은 그 다음 회신에서 파일이 바뀐 것을 확인하고 판정을 갱신했다.

## 검증

재평가 회신이 내가 붙인 md5 와 같은 값을 적었고, 반영한 항목을 라인 단위로 확인했다.

## 배운 점

worktree 절대경로는 스폰 프롬프트뿐 아니라 매 재요청 메시지에도 다시 적는다.
팀원 회신이 직전 판정과 같으면 수정된 실제 라인을 증거로 붙여 재요청한다.
이 절차는 공용 skill 이 이미 요구하고 있고, 이번에 그 값을 실측으로 확인했다.

## 후속

skill 이 이미 같은 지시를 담고 있어 별도 규칙으로 승격하지 않는다.
