# Commander 전역·하위 출력 옵션 충돌

## 관찰

루트 명령과 `skill status`가 모두 `--json`을 선언했을 때 하위 명령의 action 인자로 받은 옵션 객체만으로는 루트 위치에 지정한 출력 옵션을 일관되게 읽을 수 없었다.

## 원인

Commander는 옵션이 선언된 명령별로 값을 보관한다.
같은 이름의 전역 옵션과 하위 옵션을 함께 지원하려면 현재 명령과 상위 명령의 옵션을 명시적으로 합쳐야 한다.

## 영향

초기 구현에서는 `dooray --json skill status`와 `dooray skill status --json` 중 한 위치의 옵션이 누락될 수 있었다.
자동화 출력 계약이 위치에 따라 달라질 위험이 생겼다.

## 대응

초기 구현의 `process.argv` 보조 판정을 제거하고, 저장소의 기존 명령 패턴과 같은 `optsWithGlobals()`로 현재 명령과 상위 명령의 옵션을 병합했다.
`--force`는 출력 옵션이 아니므로 `install`/`update` 명령 객체가 파싱한 지역 옵션만 사용한다.

## 검증

두 옵션 위치에서 JSON 파싱과 표준 오류 빈 값 검사를 수행했다.
`--quiet`도 앞·뒤 위치 모두 상태 토큰만 출력하는지 확인했다.
전체 타입 검사, 테스트, 빌드, 패키지 검증까지 통과했다.

## 배운 점

전역과 하위 명령에 같은 옵션 이름을 선언할 때는 action 인자의 지역 옵션만 신뢰하지 말고 `optsWithGlobals()`를 사용해야 한다.
이 패턴은 이미 저장소 여러 명령에서 쓰이고 있어 별도 공용 지침으로 승격하지 않는다.

## 후속

추가 조치 없음.
