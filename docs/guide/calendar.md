# 캘린더

캘린더 목록과 일정을 조회하고, 일정을 만들고 고치고 지우는 방법을 안내해요.
아직 연결하지 않았다면 [설치와 설정](setup.md)을 먼저 따라 해요.

1. [일정 보기](#일정-보기)
2. [일정 만들기](#일정-만들기)
3. [일정 고치기](#일정-고치기)
4. [일정 지우기](#일정-지우기)
5. [웹 방식](#웹-방식)
6. [자세히](#자세히)

```bash
dooray calendar list                                  # 접근 가능한 캘린더 목록
dooray calendar event list                            # 오늘 하루의 일정
dooray calendar event list --from 2026-09-20 --to 2026-09-26
dooray calendar event get <calendarId> <eventId>      # 일정 상세
dooray calendar event create <calendar> --title "휴가" --start 2026-09-18
dooray calendar event edit <calendar> <eventId> --location "회의실 B"
dooray calendar event delete <calendar> <eventId>
```

## 일정 보기

### 기간 정하기

`--from` 과 `--to` 로 볼 기간을 정해요.
`2026-09-20` 처럼 날짜만 주거나 `2026-09-20T09:00:00+09:00` 처럼 시각까지 줘요.

- 날짜만 주면 실행한 컴퓨터의 시간대로 `--from` 은 그 날 `00:00:00`, `--to` 는 그 날 `23:59:59` 로 봐요.
- 둘 다 생략하면 오늘 하루를 봐요.
- 한쪽만 주면 **그 값이 가리키는 날 하루**를 봐요. `--from 2026-10-01` 은 10월 1일 하루, `--to 2026-08-01` 은 8월 1일 하루예요.
- 한 번에 볼 수 있는 기간은 최대 50일이에요. `--from 2026-01-01 --to 2026-02-20` 은 되고 `--to 2026-02-21` 은 안 돼요.
- 일정 목록은 페이지가 나뉘지 않아요. 결과를 줄이려면 기간을 짧게 잡아요.

아래 경우는 API 를 부르기 전에 종료 코드 3 으로 끝나요.

- 형식이 어긋난 값
- `--from` 이 `--to` 보다 뒤인 범위
- `2026-02-31T25:00:00+09:00` 처럼 실제로 없는 날짜나 시각
- 50일보다 긴 기간

### 목록의 표

`event list` 의 표에는 이런 열이 있어요.

| 열 | 내용 |
| --- | --- |
| 시각 | 일정 시작 시각. 종일 일정은 아래 규칙을 따라요 |
| 제목 | 일정 제목 |
| 캘린더 | 일정이 있는 캘린더 이름 |
| 내 참여 | 내가 그 일정에 어떻게 들어가 있는지. `참석·수락`, `참조·미응답`, `주최` 처럼 적어요 |

- 내가 참여자가 아닌 일정(공유받은 캘린더의 남의 일정)은 내 참여 열을 비워 둬요.
- 하루짜리 종일 일정은 `2026-09-18 (종일)` 로 적어요.
- 여러 날 종일 일정은 마지막 날까지 `2026-09-18 ~ 2026-09-20 (종일)` 로 적어요.

### 일정 하나 자세히 보기

일정 하나는 `event get` 으로 봐요.

```bash
dooray calendar list --quiet                    # 캘린더 id 만
dooray calendar event list --quiet              # 일정 id 만
dooray calendar event get <calendarId> <eventId>
```

- 캘린더 id 는 `calendar list --quiet` 이나 `event list --json` 의 `calendar.id` 에서 얻어요.
- 일정 id 는 `event list --quiet` 로 얻어서 `event get` 의 두 번째 인자로 넘겨요.
- 참석자 이름과 본문은 `event get` 에만 들어 있어요. 목록 응답의 참석자 항목은 비어 있어요.
- `event get` 은 본문을 자르지 않고 줄바꿈을 살려 전문을 보여 줘요.

## 일정 만들기

종일 일정과 일반 일정은 만드는 꼴이 달라요.

```bash
# 종일 일정. --end 는 마지막 날이고 생략하면 하루다
dooray calendar event create "내 캘린더" --title "휴가" --start 2026-09-18 --end 2026-09-19

# 일반 일정. offset 을 붙인 일시로 주고 --end 가 필수다
dooray calendar event create "팀 캘린더" --title "주간 회의" \
  --start 2026-09-21T10:00:00+09:00 --end 2026-09-21T11:00:00+09:00 \
  --location "회의실 A" --to 홍길동 user@example.com me --alarm 10m --alarm mail:1d \
  --repeat weekly --repeat-byday MO --repeat-until 2026-12-31
```

만든 일정의 id 가 필요하면 `--quiet` 을 붙여요.

### 캘린더 정하기

첫 인자 `<calendar>` 는 캘린더 id 나 이름이에요.

- 이름은 정확히 같은 것을 먼저 찾고, 없으면 이름에 포함된 것을 찾아요.
- 여럿이 걸리면 후보를 보여 주고 멈춰요.
- 구독 캘린더는 일정을 쓸 수 없어서 이름 후보에서 빠져요.

### 종일인지 일반인지 정하기

`--start` 의 형식이 종일 여부를 정해요.

- `2026-09-18` 처럼 날짜만 주면 종일 일정이에요. `--end` 도 날짜만 주고 **마지막 날을 포함해서** 적어요.
  `--start 2026-09-18 --end 2026-09-19` 는 18일과 19일 이틀이에요. `--end` 를 생략하면 하루예요.
- `2026-09-21T10:00:00+09:00` 처럼 offset 을 붙인 일시면 일반 일정이에요. `--end` 가 필수이고 시작보다 뒤여야 해요.

아래 경우는 API 를 부르기 전에 종료 코드 3 으로 끝나요.

- 날짜와 일시를 섞은 값
- offset 이 없는 일시
- 실제로 없는 날짜와 시각
- 순서가 뒤집힌 값

### 옵션

| 옵션 | 뜻 |
| --- | --- |
| `--title` | 제목. 필수예요 |
| `--body`, `--body-file` | 본문. `-` 면 stdin 에서 읽어요. 없으면 본문 없이 만들어요 |
| `--mime-type` | 본문 형식. 기본은 `text/x-markdown` 이에요 |
| `--location` | 장소 |
| `--to`, `--cc` | 참석자와 참조자. organizationMemberId, 이메일, 정확한 이름, `me` 를 여러 개 줄 수 있어요 |
| `--alarm` | 알림. 아래에서 설명해요 |
| `--private` | 비공개 일정 |
| `--repeat` | 반복 빈도. `daily`, `weekly`, `monthly`, `yearly` 중 하나예요 |
| `--repeat-interval` | 반복 간격. 기본은 1 이에요 |
| `--repeat-until` | 반복 종료. 아래에서 설명해요 |
| `--repeat-byday` | 반복 요일. `TH`, `1 MO`(첫째 월요일), `-1 WE`(마지막 수요일) |
| `--repeat-bymonth`, `--repeat-bymonthday` | 반복 월(1-12)과 일(1-31). `18,19,20` 처럼 쉼표로 여러 개를 줄 수 있어요 |
| `--dry-run` | 일정을 만들지 않고 보낼 요청 본문을 JSON 으로 보여 줘요 |

알림(`--alarm`)은 이렇게 써요.

- `10m`, `2h`, `1d`, `1w` 처럼 시작 몇 분·시간·일·주 전인지 적어요.
- 앞에 `mail:` 을 붙이면(`mail:1d`) 메일 알림이고, 붙이지 않으면 앱 알림이에요.
- 여러 번 줄 수 있어요.
- 주지 않으면 캘린더 설정의 기본 알림이 붙을 수 있어요.

반복 종료(`--repeat-until`)는 이렇게 써요.

- 날짜만 주면 그 날 23:59:59 까지예요.
- 이미 반복 일정이던 것을 고칠 때는 그 일정의 반복 시간대 기준이에요.
- 그 밖에는 실행한 컴퓨터의 시간대 기준이에요.

참석자와 반복 옵션에는 이런 규칙이 있어요.

- 참석자는 조직 멤버만 넣을 수 있어요. 조직에 없는 이메일은 외부 초대로 보내지 않고 거부해요.
- 이름은 조직 전체에서 이름이 정확히 같은 사람만 찾아요. 같은 이름이 여럿이면 후보의 이름과 id 를 보여 주고 멈춰요. 그 id 나 이메일로 다시 줘요.
- `--repeat-*` 옵션은 `--repeat` 없이 쓸 수 없어요.

### 반복 일정 예

반복 요일과 날짜를 함께 주면 둘 다 맞는 날에 반복해요.
매월 18일에서 24일 사이의 목요일(정기점검 같은 일정)은 이렇게 만들어요.

```bash
dooray calendar event create "팀 캘린더" --title "정기점검" \
  --start 2026-10-22T10:00:00+09:00 --end 2026-10-22T12:00:00+09:00 \
  --repeat monthly --repeat-byday TH --repeat-bymonthday 18,19,20,21,22,23,24
```

### 만들기 전에 확인하기

`--dry-run` 은 일정을 만들지 않고 보낼 요청 본문을 보여 줘요.
캘린더와 참석자 이름은 실제로 조회해서 풀어요. 이름이 맞게 풀리는지 미리 확인할 때 써요.

## 일정 고치기

```bash
dooray calendar event edit "팀 캘린더" <eventId> --title "주간 회의 (변경)" --location "회의실 B"
dooray calendar event edit "내 캘린더" <eventId> --start 2026-09-25 --end 2026-09-25   # 종일 일정을 25일 하루로
```

`create` 와 같은 옵션을 받고 모두 선택이에요. **준 옵션의 항목만** 바뀌어요.
수정할 항목을 하나도 주지 않으면 편집기를 열지 않고 종료 코드 3 으로 멈춰요.

### 시각 바꾸기

시각을 바꿀 때는 일반 일정과 종일 일정 모두 `--start` 와 `--end` 를 함께 줘요.

- 지금 일정의 기간을 읽지 않아서, `--start` 만 받으면 여러 날 일정이 하루로 바뀔 수 있어요.
- 하루 일정이면 `--end` 에 같은 날짜를 줘요.
- `--end` 만 줄 수도 없어요.

### 참석자와 참조자 바꾸기

`--to` 는 참석자 목록을, `--cc` 는 참조자 목록을 준 값으로 **바꿔요**.
기존 사람에 더해지지 않으니 남길 사람도 함께 적어요.
둘 중 하나만 주면 다른 쪽은 지금 일정의 사람을 그대로 둬요. `--cc` 만 고쳐도 참석자는 빠지지 않아요.

### 알림과 비공개 바꾸기

알림과 비공개는 함께 바뀌어요.

- `--alarm` 만 주면 비공개 일정이 공개로 바뀌어요.
- `--private` 만 주면 알림이 지워져요.
- 둘 다 주면 안전해요.
- 일반 일정을 종일로 바꾸면 기존 알림이 지워져요. 필요하면 `--alarm` 을 함께 줘요.

### 반복 규칙 바꾸기

반복 규칙은 `--repeat` 을 줄 때만 바뀌어요. 규칙은 통째로 바뀌어요.

- 빈도가 지금과 같으면 주지 않은 `--repeat-interval`, `--repeat-until`, `--repeat-byday`, `--repeat-bymonth`, `--repeat-bymonthday` 는 지금 값을 유지해요.
  예를 들어 `--repeat monthly --repeat-until 2027-08-31` 은 간격과 요일 조건을 그대로 두고 종료일만 늦춰요.
- 빈도를 바꾸면 종료일만 지금 값을 유지하고 나머지 세부 값은 지워져요. 지워질 항목은 경고로 알려 줘요.
- 경고에는 지워질 값을 그대로 다시 주는 옵션(예: `--repeat weekly --repeat-byday TH`)이 함께 나와요. 수정이 끝난 뒤에 그 옵션으로 다시 실행하면 값을 되살릴 수 있어요.
- 웹에서 정한 반복 횟수처럼 CLI 옵션이 없는 값도 지워져요. 원래 값만 알려 주니 웹에서 다시 설정해요.
- 수정 전에 확인하려면 `--dry-run` 을 붙여요.

### 반복 일정의 한 회차는 고칠 수 없어요

반복 일정의 회차 id(`<eventId>-20261109T000000Z` 꼴)로는 고칠 수 없어요.
회차 id 로 고치면 남은 반복 전체가 바뀌기 때문에 종료 코드 3 으로 멈추고 원본 id 를 알려 줘요.

- 반복 전체를 고치려면 그 원본 id 로 다시 실행해요.
- 회차 하나만 바꾸는 방법은 없어요. 웹에서 고쳐요.

## 일정 지우기

```bash
dooray calendar event delete "팀 캘린더" <eventId>                 # 확인 후 삭제
dooray calendar event delete "팀 캘린더" <eventId> --yes           # 확인 없이 삭제
dooray calendar event delete "팀 캘린더" <eventId> --scope all     # 반복 일정 전체
```

삭제 전에 일정 제목과 시각을 보여 주고 확인을 받아요. 기본 답은 아니오예요.
파이프나 스크립트처럼 터미널이 아닌 곳에서는 확인을 받을 수 없어요. `--yes` 가 없으면 종료 코드 3 으로 멈춰요.

### 반복 일정은 범위를 골라요

반복 일정은 `--scope` 로 지울 범위를 골라요.

| 값 | 지우는 범위 |
| --- | --- |
| `this` | 그 회차만. 기본값이에요 |
| `from-this` | 그 회차부터 이후 전체 |
| `all` | 반복 전체 |

- 반복 일정의 한 회차 id(`<eventId>-20240228T013000Z` 꼴)는 받은 그대로 넘겨요.
- 한 회차만 지우려면 `calendar event list` 로 그 회차 id 를 찾아서 넘겨요.
- 반복 전체를 지우려면 `--scope all` 을 줘요.

반복 일정의 원본 id 에 `this` 를 주면 그 회차가 아니라 반복 전체가 지워져요.
그래서 원본 id 를 `--scope` 없이(또는 `--scope this` 로) 지우려 하면 확인을 묻기 전에 종료 코드 3 으로 멈춰요.

## 웹 방식

`auth-mode` 가 `web` 이면 캘린더 명령도 웹 화면이 쓰는 경로로 돌아요.
`--json` 은 공식 API 의 필드 이름과 구조를 그대로 써요.
지원하지 않는 명령·옵션과 빠질 수 있는 필드는 [설치와 설정](setup.md)의 「웹 방식의 지원 범위」 에서 확인해요.

## 자세히

### 한쪽만 준 기간을 하루로 늘리는 이유

서버는 `--from` 이나 `--to` 중 한쪽만 받으면 기간을 걸지 않은 것과 같은 결과를 줘요.
그래서 `dooray` 는 언제나 양끝을 채워서 보내요.
한쪽만 주면 그 값이 가리키는 날 하루로 채워서 보내요.
