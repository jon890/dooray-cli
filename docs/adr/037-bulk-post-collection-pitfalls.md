## ADR-037: 업무 대량 수집 시 Dooray API 함정 (그룹 담당·조용한 속도 제한·목록 응답 body 부재)

**결정**: 본인 관련 업무를 판정할 때 `users.from`, `users.to[].member`, `users.to[].group.members[]`, `users.cc` 네 곳을 모두 본다.
목록 조회는 초당 4회 이하로 묶고, `totalCount`가 0이 아닌데 `result`가 비면 성공이 아니라 속도 제한으로 처리한다.
본문은 목록 응답에 없으므로 후보를 로컬에서 좁힌 뒤 건별로 조회한다.

**대체된 부분**: 제한을 "초당 5회" 로 본 서술은 [ADR-039](039-rate-limit-token-bucket.md) 가 정정했다.
실제로는 버스트 20개에 초당 5개를 충전하는 토큰 버킷이며, 서버가 응답 헤더로 현재 잔량을 알려준다.
아래 "초당 5회를 넘기면" 도 "버킷을 비우면" 으로 읽는다.

**맥락**: 담당자가 개인이 아니라 팀 그룹으로 지정되는 업무가 많다.
한 프로젝트를 실측했을 때 목록 1,861건 중 개인 담당은 1건이었고, 그룹 담당까지 포함하면 254건이었다.
개인 담당만 보면 그룹으로 접수되는 대외 문의 성격의 업무가 통째로 빠진다.
그룹 구성원 정보는 목록 응답에 이미 들어 있어 추가 호출이 필요 없다.

초당 5회를 넘기면 오류 응답이 아니라 빈 결과가 돌아온다.
호출자는 정상 종료로 받아들이고, 수집 결과만 보고는 왜 비었는지 알아내기 어렵다.

목록 응답에는 `body`가 없지만 작성자·담당자는 들어 있다.
후보를 먼저 로컬에서 좁히면 건별 조회 횟수가 후보 수만큼으로 줄어든다.

**대안 기각**:

- 서버 필터(`toMemberIds`)로 담당 업무만 받기 — 그룹 담당이 걸러지지 않아 위 누락이 그대로 발생한다.
- 재시도만으로 속도 제한 대응 — 빈 결과는 실패로 보이지 않아 재시도가 발동하지 않는다. 감지 조건을 명시해야 발동한다.

**적용 범위**: 다건을 훑는 수집 워크로드에 해당한다.
단건 조회 위주인 기존 CLI 명령은 초당 제한에 닿지 않으므로 속도 제어를 넣지 않는다.
