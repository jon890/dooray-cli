## ADR-040: 웹 메일 주소의 mail id 를 시각으로 풀어 IMAP UID 를 찾는다

**결정**: `dooray mail get` 과 `dooray mail reply` 가 메일 웹 주소와 그 주소의 19자리 mail id 를 받는다.
mail id 에서 도착 시각을 꺼낸 뒤, 그 시각으로 UID 를 이분 탐색해 조회한다.
시간으로 추정한 메일에 답장할 때는 제목, 발신자, IMAP 도착 시각과 UID 를 보여주고 원본 확인을 요구한다.
TTY 확인의 기본값은 아니오이며 거절하면 발송 없이 정상 취소한다.
`-y` 또는 `--yes` 로 확인을 생략할 수 있고, non-TTY 에서 이 옵션이 없으면 설정과 IMAP 조회 전에 종료 코드 3으로 중단한다.
UID 직접 입력의 답장은 기존처럼 확인 없이 보낸다.

**맥락**: 사람이 메일을 공유할 때 실제로 건네는 값은 웹 주소다.

```
https://<tenant>.dooray.com/mail/systems/inbox/<mail-id>
```

Dooray 는 메일 조회 REST API 를 제공하지 않아 이 기능은 IMAP 위에 있고 (ADR-012), 주소의 mail id 와 IMAP UID 는 체계가 다르다.
그래서 둘을 잇는 경로를 실제 사서함으로 찾았다.

메일 헤더를 거치는 경로는 막혀 있다.
`X-Dooray-Mail-Id` 헤더가 있기는 하지만 받은 메일함의 약 17% 에만 붙고, 공유받은 주소의 id 와 값이 일치하지 않는다.
IMAP 서버도 `HEADER x-dooray-mail-id <값>` 검색에 빈 결과를 준다. 같은 형식의 `message-id` 검색은 정상 동작하므로 이 헤더를 색인하지 않는 것이다.

대신 **id 자체가 시각을 담고 있다**. Dooray id 는 아래 구조다.

```
mailId = (도착시각_ms - 1262304000000) × 2^23 + 일련번호
```

빼는 값은 2010-01-01T00:00:00Z 다.
실제 주소 두 건으로 확인한 결과, 되돌린 시각과 IMAP 도착 시각의 차이가 각각 336ms 와 245ms 였다.

그리고 IMAP UID 는 도착 순서대로 증가한다.
받은 메일함 3879통에서 역전은 1건뿐이고, 그마저 2023년에 다른 폴더에서 옮겨진 것으로 보이는 단발이다.
따라서 시각을 알면 UID 를 이분 탐색할 수 있다. 3879통 기준 11~12회 조회로 끝난다.

**대안 기각**:

- 헤더를 클라이언트가 직접 훑어 매핑 — 위 이유로 값이 애초에 일치하지 않는다. 비용도 헤더만 받아 200통 약 7초, 1000통 약 67초라 단건 조회에 쓸 수 없다.
- 입력을 UID 로 간주하고 그대로 서버에 넘기기 — 이 동작이 원래의 결함이다. 19자리는 JavaScript 안전 정수 범위를 넘어 `Number()` 를 거치면 값이 바뀌고, 사용자는 입력하지 않은 숫자가 적힌 오류를 받는다.
- 사서함 전체의 도착 시각을 받아 선형 탐색 — 3879통에 약 2분이 걸린다. 이분 탐색과 결과가 같은데 비용만 크다.

**모호한 경우**: 초 단위로 겹치는 메일이 있다.
받은 메일함 3879통 중 33통(0.9%)이 앞뒤 메일과 1초 창에서 구분되지 않는다.
이때는 임의로 하나를 고르지 않고 후보 목록을 보여주고 멈춘다. 이 레포의 resolver 가 모호한 입력을 다루는 방식과 같다.

**정밀도**: 분류를 조회보다 앞에 두어 안전 정수 범위 밖 값이 `Number()` 에 도달하지 않게 한다.
UID 여부는 32비트 경계로 가른다. IMAP UID 는 32비트 부호 없는 정수라 최대 4294967295 이므로, 그 범위를 넘는 숫자는 UID 일 수 없다.
경계 비교와 시각 계산은 모두 `BigInt` 로 한다. `Number()` 로 하면 판정하려는 정밀도를 판정하는 자리에서 다시 잃는다.

**탐색 폴더**: 시스템 폴더 `inbox`, `sent`, `draft`, `archive`, `spam`, `trash` 를 지원한다.
`inbox` 는 IMAP 의 `INBOX` 에 대응하고 나머지는 같은 이름의 사서함에서 찾는다.
지원하지 않는 폴더나 시스템 폴더 형식이 아닌 메일 주소, mail id 와 UID 직접 입력은 `INBOX` 를 사용한다.

**한계**: 지원하는 시스템 폴더 주소는 해당 폴더 안에서만 탐색한다.
메일이 다른 폴더로 옮겨졌거나 삭제됐으면 찾지 못할 수 있고, UID 순서와 도착 시각이 역전된 구간에서도 탐색이 빗나갈 수 있다.
그러나 시간 일치만으로는 같은 메일이라는 것을 보장할 수 없다.
독립 코드 리뷰에서 실제 resolver 에 IMAP 대역을 연결하고, 원래 대상 없이 같은 시각의 다른 메일 하나만 남긴 경우 그 UID 가 반환되는 것을 재현했다.
따라서 조회 결과를 확인해야 하며, 되돌릴 수 없는 답장 발송에는 위의 원본 확인 절차를 둔다.
`--yes` 를 쓰는 호출자는 추정된 원본이 맞는지 확인할 책임을 갖는다.

후보가 없거나 조회 결과가 불완전하면 중단한다.
받은 메일함에서는 `mail list --search` 우회를 안내하고, 다른 사서함에서는 웹 메일의 해당 폴더에서 확인하도록 안내한다.
