## ADR-071: 메일 첨부는 순번으로 고르고, 기존 파일을 덮어쓰지 않으며, 대상 메일은 확인 없이 알리기만 한다

- **status**: `accepted`

- **결정**: `dooray mail attachment <target>` 이 메일 첨부를 파일로 저장하고, `mail get` 이 첨부 목록을 보여 준다.
  - **첨부는 `mail get` 이 보여 주는 1부터 시작하는 순번으로 고른다.** `--id <순번>` 은 여러 번 줄 수 있고, 주지 않으면 모두 저장한다.
    IMAP 에는 업무 첨부 같은 안정적인 첨부 식별자가 없다. 같은 메일은 항상 같은 순서로 파싱되므로 순번이 그 자리를 대신한다.
  - **저장 자리에 같은 이름의 파일이 있으면 그 첨부를 실패로 세고 덮어쓰지 않는다.** `--force` 를 줄 때만 덮어쓴다.
    업무·위키 첨부 다운로드는 조용히 덮어쓰는데, 메일 첨부의 파일명은 임의의 발신자가 정한다.
    업무·위키 쪽은 이번에 바꾸지 않는다.
  - **한 메일 안에서 이름이 겹치면 두 번째부터 `<이름>-<순번><확장자>` 로 저장한다.**
    `--force` 가 같은 메일의 첨부끼리 서로 덮어쓰는 일을 막으려는 규칙이다.
    겹침 비교는 NFC 정규화 뒤 대소문자를 구분하지 않는다. 바꾼 이름이 또 겹치면 `<이름>-<순번>-<n><확장자>` 로 n 을 2부터 올린다.
  - **저장 이름은 NFC 정규화와 `basename` 과 제어 문자 제거를 거친다 (`sanitizeFileName`, ADR-067).**
    쓸 수 없거나 255바이트를 넘으면 `attachment-<순번>` 으로 저장한다.
  - **`mail get` 은 첨부가 있을 때만 평문 출력에 목록을 더하고, `--json` 에는 `attachments` 배열을 항상 둔다.**
    각 항목은 `index`, `fileName`, `size`, `contentType`, `inline` 이다. 첨부가 없으면 빈 배열이다.
  - **입력 형식은 `mail get` 과 같다 (UID, 메일 웹 주소, mail id).** 저장 전에 확인을 묻지 않고, 어느 메일에서 받았는지를 평문, `--json`, `--quiet` 모두 stderr 에 한 줄로 알린다.
- **맥락**: 메일 본문은 읽을 수 있어도 첨부를 받을 방법이 없어, 메일을 읽고 이어서 처리하는 에이전트 흐름이 이 단계에서 사람 손을 탔다 (Issue #222).
  `getMail` 은 이미 `simpleParser` 로 원문 전체를 파싱하므로 첨부 메타데이터를 얻는 데 IMAP 왕복이 늘지 않는다.
- **대안 기각**:
  - `--out` 옵션 이름: 업무·위키 다운로드의 `-o, --output <dir>` 과 갈라진다. 댓글 첨부가 이미 `--out` 이라 갈라져 있는데 하나 더 늘리지 않는다.
  - MIME part 번호(`2.1` 형태)를 식별자로 쓰기: IMAP 이 실제로 쓰는 값이라 정확하지만, 사람과 에이전트가 읽기 어렵고 `mailparser` 가 이 값을 주지 않아 구조를 직접 훑어야 한다.
  - 평문 출력을 `--with-attachments` 옵션 뒤로 두기: ADR-056 은 추가 호출이 드는 보강값을 명시 옵션으로 열라는 결정이다. 첨부 목록은 이미 받은 원문에서 나와 추가 호출이 없고, 옵션 뒤에 두면 에이전트가 옵션을 알아야 첨부를 알 수 있다.
  - 메일 웹 주소와 mail id 입력에 답장처럼 확인 절차(ADR-060)를 두기: 두 입력은 도착 시각으로 원본을 추정하므로 다른 메일이 선택될 수 있다. 하지만 답장은 외부로 발송되어 되돌릴 수 없고, 첨부 저장은 로컬 파일 생성이며 기존 파일은 덮어쓰지 않는다. 대신 대상 메일의 제목과 UID 를 stderr 로 알려 자동화가 틀린 메일을 알아챌 수 있게 한다.
- **결과**:
  - 얻는 것: 에이전트가 메일 읽기부터 첨부 사용까지 사람 없이 잇는다. 순번이 `mail get` 출력과 같아 호출 두 번으로 끝난다.
  - 감당할 것: 첨부 용량만큼 메모리를 쓴다 (원문 전체를 읽는 `getMail` 과 같은 한계). 메일에 첨부가 추가되거나 파싱 결과가 달라지면 같은 순번이 다른 파일을 가리킬 수 있다. 덮어쓰기 규칙이 업무·위키 다운로드와 다르다.
- **적용 범위**: `mail get` 의 출력과 `mail attachment`. 업무·위키·댓글 다운로드와 `mail reply` 는 바꾸지 않는다.
