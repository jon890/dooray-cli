## ADR-036: 삭제 명령 공통 확인·비대화형 선차단 정책

**결정**: 되돌릴 수 없는 여섯 삭제 명령은 확인을 기본으로 하고 `-y`와 `--yes`를 같은 우회 옵션으로 제공한다.
플래그가 없는 TTY 실행은 기본값이 아니오인 확인을 거치며, 거절하면 삭제 API를 호출하지 않고 정상 취소한다.
플래그가 없는 non-TTY 실행은 설정 조회와 식별자 해석을 포함한 API 접근 전에 종료 코드 3으로 중단한다.

**맥락**: 삭제 명령마다 확인 여부와 우회 옵션이 달라 사용자가 즉시 삭제 여부를 예측하기 어려웠다.
자동화 호출자는 명령별 예외를 기억해야 했고, 확인이 있다고 오인하면 복구할 수 없는 삭제가 즉시 실행될 수 있었다.
반대로 비대화형 환경에서 프롬프트를 열면 입력을 기다리며 멈출 수 있으므로 명시적 동의 없이 진행해서는 안 된다.

**대안 기각**:

- 기존 동작 유지 — 명령마다 안전성과 자동화 인터페이스가 달라 같은 오인 위험을 남긴다.
- 확인 없이 즉시 삭제로 통일 — 자동화 호환성은 단순하지만 사람과 에이전트의 실수를 복구할 수 없다.
- 명령마다 확인 로직 유지 — 옵션·종료 코드·API 호출 순서가 다시 어긋날 가능성이 높아 공통 정책을 보장하지 못한다.
- non-TTY에서 식별자 해석 후 중단 — 삭제는 막아도 불필요한 네트워크 요청과 인증·권한 오류가 확인 정책보다 먼저 발생한다.

**트레이드오프**: 기존에 즉시 삭제되던 네 명령을 비대화형으로 호출하는 자동화는 `-y` 또는 `--yes`를 추가해야 한다.
이 호환성 비용을 감수하고 명시적 동의가 없는 파괴적 실행을 차단한다.

**적용 범위**: 업무·위키의 페이지, 댓글, 첨부 파일을 삭제하는 여섯 명령에 적용한다.
메일 인증정보 제거처럼 원격 업무 데이터를 삭제하지 않는 명령은 이 결정의 범위 밖이며 기존 정책을 유지한다.
