## ADR-062: 공식 문서에 없는 endpoint 는 조건 넷을 채운 읽기 전용에만 쓴다

**결정**: 공식 API 문서에 실리지 않은 endpoint 는 기본으로 쓰지 않는다.
쓰려면 읽기 전용이어야 하고 아래 네 가지를 모두 채워야 한다.

**대체된 부분**: 인증 방식이 `web` 일 때의 웹 경로(`/wapi`·`/v2/wapi`)에는 이 ADR 의 「읽기 전용」 과 조건 1~4 대신 [ADR-080](080-web-session-auth.md) 이 적용된다. 공개 API 방식의 비공식 경로에는 이 ADR 이 그대로 적용된다.

**맥락**: [ADR-046](046-official-api-doc-precedence.md) 이 공식 문서를 저장소 서술보다 앞에 두기로 정했지만,
문서에 아예 없는 경로를 만났을 때 무엇을 해야 하는지는 정하지 않았다.

[ADR-061](061-messenger-logs-read.md) 의 `GET /messenger/v1/channels/{channel-id}/logs` 가 그 첫 사례다.
`pnpm api:inventory` 가 「구현에 있고 공식에 없는 것: 1건」 으로 잡아냈지만,
그것이 비공식 경로라는 뜻인지 스냅샷이 낡았다는 뜻인지 스크립트는 가려내지 못한다.
사람이 공식 문서를 열어야 답이 나온다.

같은 일이 반복되면 두 가지가 무너진다.
「구현에 있고 공식에 없는 것」 이 0건이어야 정상이라는 판정을 쓸 수 없게 되고,
쓰는 사람은 자기가 부르는 명령이 호환을 약속받았는지 알 수 없게 된다.

**조건 넷**:

1. **공식 문서를 화면으로 열어 없다는 것을 확인한다.** 확인한 날짜와 본 절의 이름을 ADR 에 적는다.
   `docs/api/official-endpoints.txt` 와 대조하는 것만으로는 모자라다.
   그 파일은 특정 시점의 스냅샷이라 낡았을 수 있다.
2. **동작을 실측으로 ADR 에 남긴다.** 응답 형태, 파라미터가 먹는지, 상한, 정렬을 적는다.
   문서가 없으므로 이 ADR 이 유일한 명세가 된다.
3. **`scripts/api-endpoint-inventory.mjs` 의 `KNOWN_UNDOCUMENTED` 에 경로와 사유를 등록한다.**
   그러면 「구현에 있고 공식에 없는 것」 이 다시 0건이 되고,
   나중에 스냅샷이 낡아 생긴 차이가 이 항목에 묻히지 않는다.
4. **사용자에게 보이는 곳에 적는다.** `README.md` 와 `skills/dooray-cli/SKILL.md` 와
   그 명령의 `--help` 설명 셋에 예고 없이 막히거나 응답이 바뀔 수 있다는 것을 적는다.
   쓰는 사람이 자동화에 넣기 전에 판단할 수 있어야 한다.

**읽기 전용으로 제한하는 이유**: 문서에 없는 경로는 호환을 약속받지 못한다.
조회가 막히면 그 명령이 실패할 뿐이지만, 생성이나 수정이나 삭제가 예고 없이 바뀌면
데이터가 의도와 다르게 남는다. 되돌리는 비용이 다르다.

읽기 전용이 아닌 비공식 경로가 꼭 필요하면 이 ADR 을 고치고 그 근거를 남긴다.

**유지**: `docs/api/official-endpoints.txt` 를 갱신할 때 `KNOWN_UNDOCUMENTED` 의 항목도 다시 본다.
공식 문서에 실리게 됐으면 목록에서 빼고 해당 ADR 과 사용자 문서의 경고 문구도 함께 지운다.

**대안 기각**:

- **비공식 경로를 아예 금지** — `messenger logs` 처럼 대체 경로가 없는 기능을 포기하게 된다.
  동작을 실측하고 위험을 알리면 쓰는 사람이 판단할 수 있다.
- **스냅샷에 비공식 경로를 끼워 넣기** — 스냅샷은 공식 문서를 그대로 옮긴 것이라는 성질을 잃는다.
  그 파일이 무엇의 사본인지 알 수 없게 되면 다음 갱신에서 무엇을 지우고 무엇을 남길지 정할 수 없다.
- **`KNOWN_UNDOCUMENTED` 없이 ADR 에만 적기** — 스크립트가 매번 1건을 올리므로
  「구현에 있고 공식에 없는 것」 이 0건이어야 정상이라는 판정을 더는 쓸 수 없다.
