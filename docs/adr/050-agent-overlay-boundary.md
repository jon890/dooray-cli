## ADR-050: 전용 agent 는 도구 제한이 필요할 때만 두고, 그 밖의 저장소 지침은 오버레이가 싣는다

- **status**: `accepted`

- **결정**: `.claude/agents/` 의 전용 agent 는 `disallowedTools` 로 도구를 제한해야 하는 역할에만 둔다.
  그 밖의 저장소 고유 지침은 `.claude/*-overlay.md` 가 싣고, 공용 코어의 역할 계약을 덮지 않는다.

  `dooray-cli-executor` 를 없애고 그 내용을 `build-with-teams` 오버레이로 옮긴다.
  `dooray-cli-docs-verifier` 는 `docs-check` 전용으로 좁히고,
  `build-with-teams` 는 코어 `role-docs-verifier.md` 를 쓴다.

- **맥락**: 전용 agent 둘이 공용 코어의 역할 계약을 덮으면서 계약의 일부를 잃었다.

  `dooray-cli-executor` 는 코어 `role-executor.md` 가 요구하는 것을 담지 않는다.
  `grep` 으로 확인했고 0건이다.

  | 코어가 요구하는 것 | 전용 agent |
  | --- | --- |
  | 테스트를 작성하고 통과시킨 뒤 완료 보고 | 없음 |
  | 테스트 범위 넷 | 없음 |
  | 단언 대상 셋 | 없음 |
  | 테스트 품질 넷 | 없음 |
  | 중단 조건 넷과 `EXECUTOR_ESCALATE` | 없음 |

  `dooray-cli-docs-verifier` 는 계약이 다른 두 호출자를 한 파일이 섬긴다.
  `docs-check` 오버레이가 그것을 단일 소스로 못 박고 `build-with-teams` 오버레이도 같은 agent 를 지정한다.
  그래서 `docs-check` 의 6축이 `build-with-teams` 의 3축을 덮었다.

  잃은 것이 가장 무거운 판정의 근거다.
  코어는 `VIOLATION` 을 「accepted ADR 과 이번 변경을 대조한다」에서 내는데,
  6축 어디에도 그 축이 없어 지금은 개인 식별 정보 노출만 `VIOLATION` 이다.
  코어가 정한 「`docs/` 를 코드에 맞춰 고치는 것으로 처리하지 않는다」도 그 agent 에 없다.
  근거 형식도 다르다. 코어는 문서와 코드의 줄을 짝지어 요구하고 agent 는 한쪽만 낸다.

- **왜 오버레이로 충분한가**: 코어가 이미 오버레이에 필요한 것을 위임하고 있다.
  `SKILL.md:31` 이 「넷에 어느 에이전트를 쓸지는 오버레이가 지정한다」고 적고,
  `SKILL.md:141` 과 `role-docs-verifier.md:14` 가 「오버레이가 추가한 문서 경로」를 스폰 프롬프트에 담는다.
  그래서 저장소 고유 지침을 문서로 두고 오버레이가 그 경로를 넘기면, 코어 계약을 덮지 않고 얹을 수 있다.

  `model` 은 스폰 시점에 값으로 넘길 수 있어 agent 파일이 필요하지 않다.

- **왜 `disallowedTools` 만 남는가**: 그것만 스폰 시점에 지정할 수단이 없다.
  `dooray-cli-executor` 는 `model` 만 갖고 도구 제한이 없어 agent 파일이어야 할 이유가 없다.
  `dooray-cli-docs-verifier` 는 `disallowedTools: Write, Edit` 을 갖는다.

  그 보장은 완전하지 않다. `Bash` 가 남아 있어 리다이렉트로 파일을 쓸 수 있고,
  실제 경계는 본문의 「docs 와 코드를 직접 수정하지 않는다」다.
  그래도 검토 전용 역할에서 편집 도구를 막는 것은 값이 있어 `docs-check` 경로에서 유지한다.

- **대안 기각**:
  - 전용 agent 둘을 유지하고 코어 계약을 본문에 베껴 넣는다.
    같은 계약이 두 곳에 생겨 코어가 바뀔 때 갈라진다. 이번 유실이 그 형태로 생겼다.
  - 전용 agent 둘을 모두 없앤다. `docs-check` 경로에서 편집 도구 제한이 사라진다.
  - 코어 역할 계약을 이 저장소용으로 포크한다. 공용 코어를 쓰는 이유가 사라진다.
  - 지금 상태를 두고 유실된 계약만 agent 본문에 더한다.
    계약이 코어와 agent 두 곳에 있게 되고, 어느 쪽이 소유자인지 다시 알 수 없다.

- **결과**:
  - 얻는 것: 코어 역할 계약이 다시 권위를 갖는다. executor 의 테스트와 중단 조건이 돌아오고,
    `build-with-teams` 의 docs 검토에 ADR 위반 축이 돌아온다.
    코어가 계약을 고치면 이 저장소가 그것을 그대로 받는다.
    저장소 고유 지침이 오버레이 한 곳에 모여 어디를 봐야 하는지가 정해진다.
  - 감당할 것: `docs-check` 와 `build-with-teams` 가 서로 다른 축으로 docs 를 본다.
    두 스킬의 목적이 다르므로 의도된 것이지만, 한쪽만 돌린 결과를 다른 쪽의 판정으로 읽으면 어긋난다.
    오버레이가 길어진다. 지금 40줄 아래인 파일에 executor 지침이 더해진다.

- **적용 범위**: `.claude/agents/` 에 새 agent 를 만들 때 이 기준을 적용한다.
  `disallowedTools` 가 필요하지 않으면 오버레이에 싣는다.

  코어가 오버레이에 위임하는 일곱 중 둘이 지금 비어 있다.
  「브랜치 이름 형식, 작업 공간을 만들고 정리하는 방법」과
  「`index.json` 필드와 phase 파일 규격의 레포 변형」이다.
  비어 있으면 코어가 사용자에게 되묻는 경로로 떨어지므로 함께 채운다.
