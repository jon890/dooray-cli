## ADR-044: post 입력 오류는 실제 실행 인자를 고쳐 만든 완성 명령을 보여준다

- **status**: `accepted`

- **결정**: post 입력 분류가 안내 오류를 던질 때, 실행된 인자에서 positional 을 빼고 `--id <postId>` 를 끼운
  명령 한 줄을 보여준다. 옵션을 다시 조립하지 않고 사용자가 준 토큰을 그대로 옮기며,
  값에 공백이나 셸 특수문자가 있으면 따옴표로 감싼다.
  안내 문구를 만드는 곳을 하나로 두고 post 하위 명령 전체가 그것을 쓴다.

- **맥락**: 업무에 댓글을 남기려던 사용자가 안내를 그대로 따랐는데 두 번째 오류를 만났다 (Issue #154).

  ```
  $ dooray post comment add <project> <internal-id> --body-file ./body.md
  오류: "<internal-id>" 는 내부 ID(postId)로 보입니다.
  업무 번호(#N)가 아닌 내부 ID 로 조회하려면 --id 옵션을 사용하세요:
    dooray post get --id <internal-id>

  $ dooray post comment add <project> --id <internal-id> --body-file ./body.md
  오류: --id/--url과 positional 인자(<project> <post-number>)는 동시에 사용할 수 없습니다.
  ```

  안내가 세 가지를 빠뜨렸다.
  실행한 명령이 `post comment add` 인데 `post get` 을 보여주고,
  `--id` 를 쓰라면서 project 를 함께 빼야 한다는 말을 하지 않고,
  원래 쓰던 `--body-file` 이 사라져 그 줄을 복사하면 본문이 빠진다.

  원인은 `src/resolvers/post-input.ts` 가 자기를 부른 하위 명령을 모르는 것이다.
  20여 개 명령이 같은 `resolvePostInput` 을 부르는데 안내 문구는 `post get` 으로 고정되어 있다.

  ADR-020 이 정한 입력 통합의 방향은 유지한다.
  그 ADR 은 positional numeric 을 postId 로 자동 인식하는 것을 두 번 기각했고,
  15자리 임계가 임의값이라 ID 체계가 바뀌면 자동 인식만 틀리고 `--id` 명시 경로는 영향받지 않는다는 것이 근거였다.
  따라서 이 오류는 실수를 막는 장치가 아니라 의도된 설계이고, 이번 변경은 그 안내의 완성도만 올린다.

  옵션을 다시 조립하지 않는 이유가 있다.
  `post comment add` 만 해도 `--body`, `--body-file`, `--mention`, `--mention-group`, `--link-task`, `--dry-run` 을 받고
  명령마다 목록이 다르다. 조립 코드를 두면 옵션이 늘 때마다 그곳도 함께 고쳐야 하고,
  잊으면 안내에서 옵션이 조용히 빠진다.
  실행된 인자를 옮기면 옵션이 몇 개든 무엇이든 그대로 남는다.

  인자를 옮길 때 옵션 값을 positional 로 착각하지 않아야 한다.
  `--body-file 337` 처럼 옵션 값이 업무 번호와 같은 문자열일 수 있다.
  그래서 앞에서부터 훑으며 `--` 로 시작하는 토큰의 다음 토큰은 값으로 건너뛰고, 그 밖의 자리에서만 positional 을 제거한다.

- **대안 기각**:
  - 명령과 무관한 일반 문구로 고친다. project 를 빼야 한다는 것은 알릴 수 있지만
    실행한 명령 이름을 넣을 수 없어 `dooray <명령> --id ...` 까지만 쓸 수 있다.
  - 호출부마다 명령 이름을 문자열로 넘긴다. 명령 이름이 바뀌면 문자열이 갈라지고 검사가 잡지 못한다.
  - positional 에 온 postId 를 그대로 받아들여 오류를 없앤다.
    ADR-020 이 기각한 자동 인식이고, ID 체계가 바뀌면 조용히 틀리는 경로가 생긴다.
  - 안내에 사용자 옵션을 그대로 두지 않고 `[나머지 옵션은 그대로]` 로 적는다.
    한 줄이 짧아지지만 복사해 바로 실행할 수 없어 이슈가 지적한 왕복이 남는다.

- **결과**:
  - 얻는 것: 오류 한 줄을 복사해 붙이면 그대로 실행된다.
    실행한 명령이 무엇이든 그 명령 이름이 안내에 나오고, `--body-file` 처럼 되풀이하기 번거로운 옵션이 유지된다.
    옵션이 새로 늘어도 안내를 고칠 일이 없다.
  - 감당할 것: 안내를 만드는 쪽이 실행된 인자를 알아야 하므로 `resolvePostInput` 이 그 값을 받는다.
    호출부 20여 곳에 인자 하나를 넘기는 수정이 따라온다.
    셸이 이미 벗겨낸 따옴표는 복원할 수 없어, 다시 감쌀 때 사용자가 원래 쓴 인용 방식과 다를 수 있다.

- **적용 범위**: post 하위 명령 전체가 대상이다.
  안내를 만드는 함수는 `src/utils/` 에 두고 순수 함수로 유지해 단위 테스트로 회귀를 막는다.
  위키 쪽 `resolveWikiPageInput` 은 같은 형태의 안내를 갖지만 이번 범위에 넣지 않는다.
