## ADR-077: 발송한 메일은 같은 원문을 보낸메일함에 넣고, 저장이 실패해도 재발송하지 않는다

- **status**: `accepted`

- **결정**: `mail send` 와 `mail reply` 는 SMTP 발송이 끝난 뒤 같은 원문을 IMAP `APPEND` 로 보낸메일함에 넣는다.

  - 원문(RFC 822)은 `MailComposer` 로 한 번만 만든다. 그 바이트를 SMTP 에 `raw` 와 `envelope` 로 보내고, 같은 바이트를 `APPEND` 한다. 수신자는 `to`, `cc`, `bcc` 를 envelope 에 모두 담고, 원문에는 `Bcc` 헤더가 남지 않는다.
  - 보낸메일함은 IMAP `LIST` 가 `\Sent` 특수 용도로 알린 메일함이다. imapflow 가 메일함 이름으로 추정한 값(`specialUseSource: "name"`)은 인정하지 않는다. 없으면 저장을 건너뛰고 stderr 로 경고한다.
  - `\Seen` 플래그를 붙여 넣는다.
  - `--no-save-sent` 를 주면 IMAP 연결을 열지 않는다. 기본은 저장한다.
  - `--json` 출력에 `savedToSent` 를 더한다. 저장에 실패하면 `saveSentError` 에 이유가 든다. `--no-save-sent` 이면 `savedToSent` 는 false 이고 `saveSentError` 는 없다.
  - **발송이 성공했는데 저장만 실패하면 재발송하지 않는다.** stderr 로 경고하고 종료 코드는 0 이다. 경고에는 다시 보내지 말라고 적는다.

- **맥락**: SMTP 는 전달만 하고 보낸메일함 저장은 클라이언트가 IMAP `APPEND` 로 하는 일이다.
  그동안 CLI 로 보낸 메일은 보낸메일함에 남지 않았다([ADR-060](060-mail-reply-confirmation-policy.md)이 실측했다).

  발송은 되돌릴 수 없다. 저장 실패를 오류로 끝내면 호출자는 메일이 나갔는지 알 수 없고, 재시도하면 같은 메일이 받는 쪽에 두 통 간다.
  그래서 저장은 발송의 부가 효과로 취급하고, 실패는 경고와 `--json` 필드로만 알린다.

  원문을 두 번 만들면 Message-ID 와 Date 가 달라져 보낸메일함의 메일이 실제로 나간 메일과 다른 메일이 된다.
  그래서 한 번 만든 바이트를 두 곳에 쓴다.

- **Dooray 가 `\Sent` 를 알리는지**: 저장소 ADR 과 공식 도움말에서 확인하지 못했다. 실제 서버에는 접속하지 않았다.
  알리지 않으면 저장은 건너뛰고 경고가 나오므로 발송 동작은 달라지지 않는다. 머지 뒤 실측으로 확인한다.

- **대안 기각**:
  - **메일함 이름 `Sent` 로 추측한다** — 서버마다 이름이 다르고, 틀리면 엉뚱한 메일함을 만들거나 실패한다.
  - **저장 실패를 오류 종료로 한다** — 호출자가 재시도하면 이중 발송이 된다.
  - **SMTP 로 보낸 뒤 원문을 다시 만들어 저장한다** — Message-ID 와 Date 가 어긋난다.
