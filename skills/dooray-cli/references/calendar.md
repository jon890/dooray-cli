# calendar

## 기간 지정

`--from` 과 `--to` 에 날짜만 주면 실행 장비의 시간대로 하루의 시작과 끝까지 늘어난다.
둘 다 생략하면 오늘 하루를 보고, **한쪽만 주면 그 값이 가리키는 날 하루**를 본다.
`--from 2026-10-01` 은 10월 1일 하루다. 오늘부터 그 날까지가 아니다. 기간을 보려면 양쪽을 다 준다.
서버는 한쪽만 받으면 그것을 무시하고 기간을 걸지 않은 것과 같은 결과를 주므로 CLI 가 언제나 양끝을 채운다.
형식이 어긋난 값, 실재하지 않는 날짜와 시각, `--from` 이 `--to` 보다 뒤인 범위는
API 를 부르기 전에 종료 코드 3 으로 거부한다.
**한 번에 조회할 수 있는 기간은 최대 50일이다.** 더 긴 기간은 50일 이하로 나눠 여러 번 부른다.

## 목록과 상세

**일정 목록은 페이징이 없다.** 결과가 많으면 기간을 나눠 여러 번 조회하는 것 말고 방법이 없다.
**참석자 이름과 본문은 `event get` 에만 있다.** 목록 응답의 참석자 항목은 비어 있으니 목록만 보고 참석자를 말하지 않는다.
다만 **내가** 참여하는지는 목록 표의 내 참여 열(`참석·수락`, `참조·미응답`, `주최` 등)로 알 수 있다. 빈 칸이면 내가 참여자가 아니다.
`event get` 에 넘길 캘린더 id 는 `calendar list --quiet` 이나 `event list --json` 의 `calendar.id` 에서 얻는다.

## 일정 쓰기

`event create`·`edit`·`delete` 의 첫 인자는 캘린더 id 나 이름이다. 구독 캘린더는 이름 후보에서 빠진다.

**종일 여부는 `--start` 형식으로 정해진다.** `2026-09-18` 처럼 날짜만 주면 종일 일정이고, 이때 `--end` 는 **마지막 날을 포함한** 날짜다.
`--start 2026-09-18 --end 2026-09-19` 는 이틀짜리다. 서버에 보내는 끝 날짜는 CLI 가 하루 더해 맞추므로 직접 더하지 않는다.
일반 일정은 `2026-09-21T10:00:00+09:00` 처럼 **offset 을 붙인 일시**로 주고 `--end` 가 필수다. offset 이 없으면 거부된다.

**참석자(`--to`·`--cc`)는 조직 멤버만 넣는다.** organizationMemberId, 이메일, 정확한 이름, `me` 를 받는다.
이름은 조직 전체에서 정확히 같은 사람만 찾고, 동명이인이면 후보의 이름과 id 를 보여주고 멈춘다. 그 id 로 다시 부른다.
조직 밖 이메일은 거부된다.

처음 쓰는 조합이면 `--dry-run` 으로 보낼 요청 본문을 먼저 확인한다. 이름 해석은 실제로 하고 일정은 만들지 않는다.
`--alarm` 은 `10m`·`2h`·`1d`·`1w` 형태이고 `mail:` 을 앞에 붙이면 메일 알림이다.
`--alarm` 을 주지 않으면 캘린더 설정의 기본 알림이 붙을 수 있다. 알림이 필요 없는 일정이면 사용자에게 알린다.
`edit` 로 일반 일정을 종일로 바꾸면 기존 알림이 지워진다. 알림을 유지해야 하면 `--alarm` 을 함께 준다.
`edit` 에서 알림과 비공개는 함께 바뀐다. `--alarm` 만 주면 비공개 일정이 공개로 바뀌고 `--private` 만 주면 알림이 지워진다.
둘 중 하나를 고칠 때는 사용자에게 현재 알림과 공개 여부를 물어 둘 다 준다. API 로는 현재 값을 읽을 수 없다.
반복은 `--repeat weekly` 같은 빈도와 `--repeat-byday`·`--repeat-until` 등 부속 옵션으로 준다. 부속 옵션만 주면 거부된다.
`--repeat-bymonthday`·`--repeat-bymonth` 는 쉼표 목록을 받는다. "매월 18-24일 사이 목요일" 은
`--repeat monthly --repeat-byday TH --repeat-bymonthday 18,19,20,21,22,23,24` 다.

**`edit` 은 준 옵션의 항목만 바꾼다.** 시각을 바꾸려면 일반 일정과 종일 일정 모두 `--start` 와 `--end` 를 함께 준다.
종일 일정의 하루짜리는 `--end` 에 같은 날짜를 준다. `--start` 만 주면 거부된다.
반복 규칙은 `--repeat` 을 줄 때만 바뀌고, 빈도가 같으면 주지 않은 `--repeat-*` 값은 지금 값이 유지된다.
빈도를 바꿔도 종료일(`--repeat-until`)은 유지되고, 나머지 세부 값은 지워진다.
빈도를 바꾸거나 반복 횟수처럼 CLI 가 다루지 않는 값이 있으면 지워진다는 경고가 stderr 에 나온다. 그 경고가 나오면 사용자에게 알린다.
경고에는 지워질 값을 되살리는 옵션(예: `--repeat weekly --repeat-byday TH`)이 함께 나온다. 사용자가 값을 유지하길 원하면 그 옵션으로 다시 실행한다.
`--to`·`--cc` 는 그 목록으로 **바꾼다**. 기존 사람에 더해지지 않으므로 사람을 추가할 때는 `event get` 으로 기존 목록을 보고
남길 사람까지 모두 적는다. 한쪽만 주면 다른 쪽은 기존 값이 유지된다.
**반복 일정의 회차 id(`<id>-YYYYMMDDTHHMMSSZ`)로는 `edit` 할 수 없다.** 회차 하나만 고칠 방법이 없어 거부되고, 오류에 원본 id 가 나온다.
사용자가 반복 전체를 고치려는 것이 확실할 때만 그 원본 id 로 다시 부른다. 회차 하나만 바꿔야 하면 웹에서 고치라고 안내한다.

**`delete` 는 확인을 받는다.** 에이전트처럼 터미널이 아닌 곳에서 부르면 `--yes` 가 필요하다.
사용자가 지우라고 한 일정이 맞는지 `event get` 으로 먼저 확인하고 `--yes` 를 붙인다.
반복 일정은 `--scope this|from-this|all` 로 범위를 고르고, 기본은 그 회차만이다.
**반복 일정의 원본 id 를 `--scope` 없이 지우면 거부된다.** 원본 id 에 `this` 를 주면 반복 전체가 지워지기 때문이다.
한 회차만 지우려면 `event list` 로 회차 id(`<id>-YYYYMMDDTHHMMSSZ`)를 찾아 넘기고, 사용자가 반복 전체를 지우라고 한 것이 확실할 때만 `--scope all` 을 준다.
