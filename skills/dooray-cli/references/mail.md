# mail

## 원본 선택과 답장 확인

메일 웹 주소와 mail id 는 도착 시각으로 원본을 추정하므로 다른 메일이 선택될 수 있다.
답장은 UID 직접 입력을 포함한 세 입력 형식 모두 발송 전에 제목, 발신자, 도착 시각과 UID 를 확인하며 기본값은 아니오다.
자동화에서 답장하려면 원본이 맞는지 확인한 뒤 `-y` 또는 `--yes` 를 명시한다.
비대화형 환경에서 이 옵션이 없으면 전송 전에 종료 코드 3으로 중단한다.

## 첨부해서 보내기

`mail send` 와 `mail reply` 는 `--attach <paths...>` 로 파일을 붙인다. 여러 경로를 줄 수 있다.
`dooray mail reply <uid> --body-file body.md --attach photo.jpg -y` 처럼 쓴다.
경로마다 존재하는 일반 파일인지 먼저 확인하고, 없거나 디렉터리면 아무것도 보내지 않고 종료 코드 3으로 끝난다.
첨부 이름은 경로의 마지막 이름이다.
답장 확인 화면에는 첨부 이름과 크기가 나오고, `--yes` 일 때는 같은 내용을 stderr 로 알린다.
`--json` 출력의 `attachments` 는 보낸 파일 이름 목록이다.
크기 상한은 CLI 가 두지 않는다. 한도를 넘으면 SMTP 서버가 거부한다.

## 보낸메일함 저장

`mail send` 와 `mail reply` 는 발송한 원문을 그대로 보낸메일함(IMAP `\Sent`)에 읽음 상태로 넣는다. 웹에서 보낸 메일처럼 보낸메일함에서 찾고 이어서 답할 수 있다.
저장하지 않으려면 `--no-save-sent` 를 준다. 이때는 IMAP 에 접속하지 않는다.
발송은 성공했는데 저장만 실패하거나 서버가 `\Sent` 메일함을 알리지 않으면, 메일을 다시 보내지 않고 stderr 로 경고하며 종료 코드는 0 이다. 경고를 보고 같은 명령을 다시 실행하지 않는다. 같은 메일이 한 번 더 나간다.
`--json` 출력의 `savedToSent` 가 저장 결과이고, 실패하면 `saveSentError` 에 이유가 든다. 자동화에서는 이 값을 확인한다.

## 첨부 저장

`dooray mail get` 이 첨부 목록을 1부터 시작하는 순번과 함께 보여 준다. `--json` 은 `attachments` 배열을 준다.
각 항목은 `index`, `fileName`, `size`, `contentType`, `inline` 이다.
`dooray mail attachment` 의 `--id` 는 이 순번이다. 여러 번 줄 수 있고, 주지 않으면 모두 저장한다.

저장 자리에 같은 이름의 파일이 있으면 그 첨부는 실패하고 종료 코드 1로 끝난다. 덮어쓰려면 `--force` 를 준다.
한 메일 안에서 이름이 겹치면 두 번째부터 `<이름>-<순번><확장자>` 로 저장한다.
겹침은 NFC 정규화 뒤 대소문자를 구분하지 않고 비교하며, 바꾼 이름도 겹치면 `<이름>-<순번>-<n><확장자>` 로 n 을 2부터 올린다.
없는 순번을 주면 파일을 쓰기 전에 종료 코드 3으로 중단한다.

메일 웹 주소와 mail id 는 도착 시각으로 원본을 추정하므로 다른 메일이 선택될 수 있다.
첨부 저장은 확인을 묻지 않고, 어느 메일에서 받았는지(제목과 UID)를 `--json` 과 `--quiet` 에서도 stderr 에 한 줄로 알린다.
자동화에서는 그 줄이 의도한 메일인지 확인한다.
