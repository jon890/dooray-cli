# 문체 추출, 문서 생성, 주입

이 문서는 4단계 문체 추출, 5단계 문서 생성, 6단계 주입과 확인을 다룬다.

## 문체 추출

먼저 분류가 확정된 `classified.jsonl`에서 `label`이 `human`인 표본을 모델이 직접 읽는다.
문장 구조, 종결 방식, 정보 배열, 요청과 완곡 표현, 수신자에 따른 차이를 실제 문장과 함께 관찰한다.

보조 통계는 다음 명령으로 만든다.

```bash
node ~/.claude/skills/dooray-persona/scripts/stats.mjs
```

`stats.json`은 기호, 종결어미, 문장 길이 같은 반복을 확인하는 보강 근거다.
통계 수치만으로 문체 규칙을 만들거나 모델의 원문 읽기를 대체하지 않는다.

### 수신자 축을 표본에서 찾는다

두 모드로 갈리는 경우가 흔하지만 모드 수와 구분 기준을 미리 정하지 않는다.
`assigneeKind`, 업무 성격, 본문과 댓글의 차이, 표현이 실제로 바뀌는 지점을 함께 보고 이 사용자에게 의미 있는 수신자 축을 찾는다.
차이가 뚜렷하지 않으면 억지로 모드를 나누지 않는다.

다음 세 종류를 추출한다.

- **수신자별 모드** — 언제 쓰는지, 문장 길이, 격식, 설명 밀도, 요청 방식과 실제 예시
- **반복 습관** — 여러 모드에서 되풀이되는 도입, 연결, 목록, 마무리 방식
- **하지 않는 것** — 표본에서 일관되게 피하는 표현, 과장, 장식, 구조

`하지 않는 것`은 두 갈래로 갈라서 적는다.
금지의 근거가 표본이므로 표본의 장르를 넘어서면 근거가 사라진다.

- **어디서나 유지하는 것** — 문장을 만드는 방식이다. 표현, 과장, 강조 남용처럼 길이와 매체가 바뀌어도 유지된다.
- **짧은 글에서만 적용하는 것** — 헤더, 표, 시각 요소처럼 분량과 매체가 정하는 서식이다.

표본이 짧은 댓글에 몰려 있으면 `헤더를 쌓지 않는다`, `표로 정리하지 않는다` 같은 항목이 나온다.
이 항목들을 조건 없이 적으면 긴 안내 문서나 공개 게시글에까지 적용되어 오히려 읽기 어려워진다.
그러므로 두 번째 갈래에는 적용 범위를 함께 적는다.

표본이 어떤 종류의 글에서 왔는지도 함께 기록한다.
업무 본문과 짧은 댓글만 모였는데 규칙이 모든 글에 적용되면, 표본에 없던 장르로 댓글의 규칙이 새어 나간다.
문서를 읽는 쪽이 적용 범위를 판단할 수 있도록 표본 장르를 명시한다.

실제 예시는 `human` 표본에서 짧게 가져오되 민감한 이름과 식별자는 일반화한다.
표본이 적으면 임의의 개수 기준으로 중단하지 않는다.
사용 가능한 표본 수와 수집 기간을 보고하고, 이 근거로 계속 만들지 사용자에게 정하게 한다.

## 문서 생성

[persona.md](../templates/persona.md)를 복사해 설정의 `outputPath`에 쓴다.
대괄호 안내문을 실제 관찰 결과로 모두 바꾸고, 표본 수와 수집 기간을 명시한다.
근거 없는 특징이나 예시는 만들지 않는다.

문서 본문은 특정 에이전트나 하네스를 전제하지 않는 업무 문체 규칙으로 쓴다.
기존 문체 규칙과 충돌해 보이는 지점도 찾아 우선순위와 예외 범위를 채운다.

## 규칙 문서 주입

완성한 페르소나를 독립된 규칙 파일로 두고 사용하는 하네스가 매번 읽도록 연결한다.

Claude Code에서는 프로젝트 또는 사용자 `CLAUDE.md`에 다음과 같은 참조 한 줄을 추가한다.

```markdown
Dooray 업무 글을 작성할 때는 @~/.claude/dooray-persona.md 규칙을 함께 따른다.
```

다른 하네스에서는 같은 파일을 규칙 파일로 첨부하거나 시스템 프롬프트에서 읽도록 지정한다.
특정 하네스 문법이 다르면 그 하네스의 규칙 파일 연결 방식만 바꾸고 페르소나 본문은 유지한다.

## `dooray-cli`와 연동

Dooray 업무나 댓글을 등록하기 전에 다음 순서를 적용한다.

1. 수신자와 상황을 보고 페르소나의 모드를 고른다.
2. 기존 저장소·팀 문체 규칙을 먼저 적용한다.
3. 선택한 모드와 공통 습관으로 초안을 다듬는다.
4. 페르소나의 자가 점검 목록을 통과시킨다.
5. 등록 전 미리보기를 사용자에게 보여준다.
6. 승인된 본문을 `dooray-cli`로 등록한다.

등록 전 미리보기는 모드 판정과 자가 점검을 끼워 넣는 지점이다.
단건 조회·등록·수정 명령 자체는 `dooray-cli` 스킬의 절차를 따른다.

## 주입 확인

주입을 마치면 실제 업무 상황을 가정한 짧은 댓글 하나를 작성한다.
선택한 모드의 특징과 공통 습관이 드러나는지 확인하고 자가 점검 항목과 한 줄씩 대조한다.
맞지 않는 항목이 있으면 원문 표본으로 돌아가 규칙을 고친 뒤 다시 작성한다.
