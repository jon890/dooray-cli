# 작성 주체 분류와 사용자 확인

이 문서는 3단계에서 AI 작성분과 정형 양식을 분리하는 방법을 다룬다.

## 자동 분류 실행

수집과 같은 설정 및 작업 디렉터리를 사용해 경계 항목 보고서를 함께 만든다.

```bash
node ~/.claude/skills/dooray-persona/scripts/classify.mjs --report
```

스크립트는 `corpus.jsonl`을 읽어 `classified.jsonl`을 쓴다.
`--report` 출력에는 라벨별 개수와 `needsReview` 경계 항목이 들어 있다.

## 신호의 의미

| 신호 | 의미 |
| --- | --- |
| `headings` | 마크다운 제목 수 |
| `tableRows` | 마크다운 표 행 수 |
| `boldRuns` | 굵은 글씨 구간 수 |
| `closingSections` | 결론, 정리, 요약, 다음 단계 절 수 |
| `bullets` | 목록 항목 수. 통계에는 남지만 AI 판정의 필수 신호는 아님 |
| `emoji` | 그림문자 수. 통계에는 남지만 AI 판정의 필수 신호는 아님 |
| `chars` | 글자 수. 비교 근거이지 단독 판정 신호는 아님 |

제목, 표, 굵은 글씨, 마무리 절이 각각 기준 이상으로 함께 나타날 때만 AI 작성 의심 신호로 본다.
신호 하나만 높다고 AI 작성분으로 확정하지 않는다.

## 라벨 판정 순서

1. 같은 형태의 제목이 반복되거나 배포·릴리스·패치노트·정기 점검 지표가 있으면 `formal-template`로 먼저 분류한다.
2. 정형 양식이 아니면서 구조 신호가 모두 높으면 `ai-suspect`로 분류한다.
3. 어느 조건에도 해당하지 않으면 `human`으로 분류한다.
4. 선택적인 세션 로그 대조에서 등록 기록이 확인된 댓글만 `ai-confirmed`로 바꾼다.

이 순서에서는 정형 양식 판정이 AI 의심 판정보다 앞선다.

## 정형 양식을 AI로 분류하지 않는 이유

헤더와 표가 많아 AI 작성처럼 보였던 글이 실제로는 사람이 쓴 배포 기록인 사례가 있었다.
정형 양식의 반복 구조는 작성 도구가 아니라 업무 형식에서 생긴다.
따라서 `formal-template`는 개인 문체 표본에서는 빼지만 AI 작성 통계에는 넣지 않는다.

## 경계 항목을 사용자와 확정

`--report`의 `needsReview` 각 항목에 제목, 상위 신호, 필요한 경우 원문 일부를 붙여 사용자에게 보여준다.
비밀이나 개인 정보가 섞일 수 있으므로 필요한 최소 범위만 제시한다.

사용자에게 다음 중 실제 작성 경위를 고르게 한다.

- 직접 쓴 개인 문체 표본이면 `human`
- 생성형 AI 결과를 그대로 또는 주로 사용했으면 `ai-confirmed`
- 사람이 채운 반복 양식이면 `formal-template`
- 판단할 수 없으면 보류하고 문체 표본에서 제외

확정 결과를 `classified.jsonl`에 반영하고 `confirmed`를 `true`로 바꾼다.
경계 항목 확인이 끝나기 전에는 문체 추출 단계로 넘어가지 않는다.

## 선택적인 세션 로그 대조

설정의 `sessionScan.enabled`가 `true`이면 다음 명령으로 로컬 에이전트 세션 기록과 댓글 등록 기록을 대조할 수 있다.

```bash
node ~/.claude/skills/dooray-persona/scripts/scan-sessions.mjs
```

일치한 댓글은 `ai-confirmed`로 갱신되어 분류 정확도가 높아진다.
설정 파일이 없거나 기능이 꺼져 있거나 로그 경로에 파일이 없으면 스크립트가 안내하고 건너뛴다.
세션 로그는 선택 기능이며, 사용할 수 없어도 사용자 확인 절차로 계속 진행한다.
