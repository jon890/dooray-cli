# 처음 쓰는 사람을 위한 설치 프롬프트

터미널 명령에 익숙하지 않은 사람에게 이 워크플로우를 넘길 때 쓴다.
아래 프롬프트를 그대로 복사해 전달하면, 받은 사람은 한 번 붙여넣는 것으로 설치부터 주입까지 끝낸다.

## 받는 사람이 프롬프트를 붙여넣을 곳

터미널을 열 필요가 없다. Claude 데스크톱 앱 안에서 끝낸다.
macOS 와 Windows 모두 같다.

1. Claude 앱을 연다.
2. 왼쪽 사이드바 맨 위의 **`Code`** 를 누른다. 옆에 있는 `홈` 이 채팅이고, `Code` 가 Claude Code 다.
3. **`폴더 선택…`** 으로 작업할 폴더를 고른다. 아무 폴더나 괜찮다. 문서는 이 폴더가 아니라 홈 디렉터리 아래에 저장된다.
4. 아래 프롬프트를 입력창에 붙여넣는다.

Claude Code 를 따로 설치하지 않는다. 앱이 직접 실행한다.

`Code` 버튼이 보이지 않으면 **조직 관리자가 Claude Code for Desktop 을 꺼 둔 것**이다.
이때는 앱만으로는 진행할 수 없으므로 관리자에게 문의하거나 터미널에서 Claude Code 를 설치해야 한다.

## 전달 전에 확인할 것

프롬프트가 대신해 줄 수 없는 것이 셋 있다.

- **앱에서 `Code` 를 누르고 폴더를 고르는 것** — 화면 조작이라 사람이 한다. 클릭 두 번이다.
- **Node.js 설치** — 설치 파일이 관리자 비밀번호를 받는 창을 띄운다. 프롬프트가 내려받을 주소를 알려 주고 끝날 때까지 기다린다.
- **Dooray 개인 인증 토큰 발급** — 웹 로그인이 필요하다. 프롬프트가 발급 화면까지 안내하지만 실제 발급과 복사는 사람이 한다.

나머지는 프롬프트가 처리한다.
CLI 설치, 설정 저장, 스킬 연결, 수집, 문서 생성, 주입이 여기 해당한다.
받는 사람이 직접 칠 명령은 하나도 없다.

토큰은 stdin 으로 저장하게 되어 있다. 명령 인자로 넘기면 셸 기록과 실행 로그에 값이 남는다.
이 경로는 `@bifos/dooray-cli` 0.18.0 부터 동작하므로, 그보다 낮은 버전이 깔려 있으면 프롬프트가 먼저 올린다.

## 전달할 프롬프트

```text
너는 내가 Dooray 업무 글 문체 페르소나를 만들도록 처음부터 끝까지 도와준다.
나는 터미널과 개발 도구에 익숙하지 않다. 아래 규칙을 지켜라.

[대화 규칙]
- 한국어로 말한다.
- 무슨 명령을 실행하는지 설명하지 말고, 지금 무엇이 일어나는지만 한 문장으로 알려준다.
- 나에게 요청할 것이 있으면 한 번에 하나만 요청한다.
- 내가 붙여넣은 인증 토큰은 화면에 다시 출력하지 않는다. 파일에 저장한 뒤에는 "저장했다"고만 말한다.
- 어떤 단계가 실패하면 원인을 한 문장으로 알려주고, 내가 무엇을 하면 되는지 알려준다. 혼자 우회하지 않는다.
- 오래 걸리는 단계는 시작 전에 예상 소요를 알려준다.

[0단계 — 운영체제 확인]
내가 macOS 를 쓰는지 Windows 를 쓰는지 먼저 확인한다.
이후 모든 명령을 그 운영체제의 기본 셸에 맞게 쓴다.
macOS 는 zsh, Windows 는 PowerShell 을 기준으로 한다.
아래에 적힌 예시는 macOS 표기다. Windows 면 같은 일을 하는 PowerShell 명령으로 바꿔서 실행한다.

[1단계 — 실행 환경 확인]
node --version 으로 Node.js 20 이상인지 확인한다.
이미 20 이상이면 아무 말 없이 2단계로 넘어간다.

없거나 20 보다 낮으면 여기서 멈추지 말고 나를 안내해서 함께 넘어간다.

- 내 운영체제를 확인한다.
- https://nodejs.org 의 LTS 설치 파일을 내려받아 실행하면 된다고 알려준다.
  macOS 는 `.pkg`, Windows 는 `.msi` 다. 내 운영체제에 맞는 것을 집어서 알려준다.
- 설치 창이 관리자 비밀번호나 권한 확인을 물어볼 수 있다고 미리 알려준다.
- 설치가 끝나면 알려 달라고 요청하고 기다린다. 임의로 다른 방법을 쓰지 않는다.
- 내가 끝났다고 하면 node --version 을 다시 확인한다.
  그래도 안 잡히면 앱을 껐다 켜야 할 수 있다고 알려주고, 다시 확인한다.

[2단계 — Dooray CLI 준비]
dooray --version 을 실행한다.

- 명령이 없으면 npm install -g @bifos/dooray-cli 로 설치한다.
- 버전이 0.18.0 보다 낮으면 같은 명령으로 최신을 설치한다.
  낮은 버전에는 다음 단계에서 쓸 토큰 저장 방식이 없어, 그대로 두면 토큰이 잘못 저장된다.
- 0.18.0 이상이면 넘어간다.

권한 오류가 나면 임의로 sudo 를 붙이지 말고 나에게 알려준다.

[3단계 — 인증 설정]
dooray config get api-key 로 이미 인증이 되어 있는지 먼저 확인한다.
출력이 (미설정) 이 아니면 4단계로 넘어간다.
설정 파일만 있고 값이 비어 있는 상태가 있으므로, 파일 존재 여부가 아니라 이 값으로 판단한다.

없으면 내가 쓰는 Dooray 주소를 묻는다. 회사 Dooray 를 열었을 때 주소창에 보이는
"https://회사이름.dooray.com" 에서 회사이름 부분이다.

그 값으로 https://회사이름.dooray.com/setting/api/token 을 만들어 나에게 알려주고,
그 화면에서 개인 인증 토큰을 발급해 붙여넣어 달라고 요청한다.

받은 값을 stdin 으로 저장한다. 토큰을 명령 인자에 넣지 않는다.
인자로 넘기면 값이 셸 기록과 실행 로그에 남는다.

  macOS
    printf '%s' '<받은 토큰>' | dooray config set api-key -
  Windows PowerShell
    '<받은 토큰>' | dooray config set api-key -

저장한 뒤 dooray config get api-key 로 (미설정) 이 아닌지 확인한다.

설정 파일이 없으면 이 명령이 만들면서 일반 Dooray 주소를 기본값으로 채우므로 접속 주소는 따로 설정하지 않는다.
회사가 공공이나 금융 전용 Dooray 를 쓸 때만 dooray config set base-url <그 환경의 주소> 를 추가로 실행한다.

앞에서 물어본 회사이름은 dooray config set tenant-name <회사이름> 으로 함께 저장한다.
나중에 안내 링크가 이 값으로 만들어진다.

dooray project list 로 목록이 나오는지 확인한다.
실패하면 토큰이 잘못됐을 가능성이 높으니 다시 발급받아 달라고 요청한다.

[4단계 — 문체 스킬 연결]
~/.claude/skills/dooray-persona 가 이미 있으면 넘어간다.

없으면 저장소 압축본을 내려받아 스킬 폴더만 꺼내 복사한다.

- git 을 쓰지 않는다. git 은 별도 설치가 필요할 수 있어 여기서 막힌다.
- 심볼릭 링크를 만들지 않고 복사한다. Windows 에서 링크는 개발자 모드나 관리자 권한을 요구한다.
- curl 과 tar 는 macOS 와 Windows 10 이상에 기본으로 들어 있다.

  빈 임시 폴더를 하나 만들고 그 안에 압축본을 풀고
    curl -fsSL https://github.com/jon890/dooray-cli/archive/refs/heads/main.tar.gz -o <임시>/dooray-cli.tar.gz
    tar xzf <임시>/dooray-cli.tar.gz -C <임시> --strip-components=1
  풀린 <임시>/skills/dooray-persona 를 통째로
    ~/.claude/skills/dooray-persona
  로 복사한다. 이미 있으면 지우고 다시 복사한다.

tar 는 -C 로 지정한 폴더가 없으면 실패한다. 풀기 전에 그 폴더가 있는지 확인한다.

Windows 에서는 curl.exe 와 tar.exe 를 쓰고, 경로는 %USERPROFILE%\.claude\skills 아래가 된다.

내려받기가 막히면 사내망 정책일 수 있으니 나에게 알려준다. 혼자 다른 경로를 찾지 않는다.
나중에 스킬을 갱신할 때는 같은 과정을 다시 실행하면 된다.

[5단계 — 내 글 수집과 페르소나 작성]
dooray-persona 스킬을 열어 그 절차를 따른다.
스킬이 정한 단계와 확인 지점을 건너뛰지 않는다. 특히 아래 둘은 반드시 나에게 묻는다.
- 어느 프로젝트에서 내 글을 모을지
- AI 가 썼는지 사람이 썼는지 애매한 글을 어떻게 볼지

수집은 글이 많으면 수십 분이 걸릴 수 있다. 시작 전에 알려주고, 중간에 진행 상황을 알려준다.

[6단계 — 실제로 쓰이게 연결]
만들어진 문체 문서를 Claude Code 가 매번 읽도록 연결한다.
연결 방법은 스킬의 주입 절차를 따른다.

연결이 끝나면 짧은 업무 댓글 하나를 예시로 써서 보여주고,
내 평소 말투와 다른 부분이 있는지 나에게 물어본다.

[마지막]
끝나면 아래를 알려준다.
- 문체 문서가 저장된 위치
- 앞으로 내 문체로 쓰게 하려면 뭐라고 말하면 되는지
- 나중에 글이 쌓였을 때 문서를 다시 만들려면 뭐라고 말하면 되는지

1단계부터 시작해라.
```

## 채팅에서만 쓰고 싶다면

앱의 `홈` 쪽 채팅은 이 사람의 컴퓨터에 있는 파일과 명령을 다루지 못한다.
수집과 문서 생성은 `Code` 에서 하고, 만들어진 문체 문서를 채팅의 프로젝트 지식이나 개인 지침에 붙여넣어 쓴다.

문서 본문은 특정 도구를 전제하지 않는 업무 문체 규칙이므로 그대로 옮겨도 동작한다.
다만 이 경우 Dooray 등록은 자동으로 되지 않는다. 본문을 받아 사람이 붙여넣는다.
