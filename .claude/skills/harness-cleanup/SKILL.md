# harness-cleanup

에이전트 지침이 틀리면 에이전트가 그대로 따라 실패한다.
이 스킬은 지침 파일에서 **사실 오류와 동작하지 않는 지침**을 먼저 잡고, 그다음 분량을 줄인다.

순서가 중요하다. 분량부터 줄이면 틀린 내용을 그대로 남긴 채 짧아진다.

## 대상

| 유형 | 경로 예 |
| --- | --- |
| 프로젝트 지침 | `CLAUDE.md` |
| custom agent 정의 | `.claude/agents/*.md` |
| 내부 워크플로 스킬 | `.claude/skills/*/SKILL.md` |
| 공용 스킬 오버레이 | `.claude/*-overlay.md` |
| 공개 스킬 | `skills/*/SKILL.md`, `skills/*/references/*.md` |

`docs/` 는 대상이 아니다. 설명이 있어야 하는 곳이다.

## 1. 규모 파악

```bash
bash scripts/collect_targets.sh
```

파일별 줄수와 합계를 낸다. 이후 단계에서 어디를 먼저 볼지 정하는 기준이다.

## 2. 참조 무결성

```bash
python3 scripts/check_references.py
```

문서가 가리키는 대상이 실재하는지 확인한다.

- 마크다운 링크
- 백틱으로 감싼 파일·디렉터리 경로
- `"섹션명" 섹션` / `"섹션명" 표` 형태의 다른 문서 섹션 참조
- `` `이름` skill `` 형태의 스킬 참조

**깨진 참조는 대개 한쪽만 고친 흔적이다.** 섹션을 지우고 그것을 가리키는 문서를 갱신하지 않으면 남는다.

## 3. 사실 대조

```bash
python3 scripts/check_facts.py
```

문서에 적힌 것과 실제를 대조한다. 자동 판정이 아니라 **검토 지점을 뽑아 준다** — 개수와 목록은 맥락을 봐야 판정된다.

- 개수 표기(`N개 명령`, `N개 파일`) — 늘거나 줄면 곧 틀린다. 개수 자체를 빼는 것이 안전하다
- 여러 문서에 나열된 같은 종류의 목록 — 서로 다르면 전부 의심 대상이다
- 문서가 언급한 CLI 옵션 — 실제 `--help` 에 있는지

## 4. 문서의 명령이 실제로 동작하는가

```bash
bash scripts/run_doc_snippets.sh <파일> "<블록을 찾을 머리말>"
```

**이 단계를 건너뛰지 않는다.** 문서에 적힌 검증 명령이 아무것도 검사하지 않는 상태를 사람이 읽어서는 발견할 수 없다.

세 가지를 본다.

- **문법** — `bash -n` 과 `zsh -n` 양쪽
- **셸 차이** — 같은 명령이 bash 와 zsh 에서 다르게 동작하는지. 배열 확장이 대표적이다
- **음성 대조** — 검사 대상 디렉터리에 일부러 탐지 대상을 심고, 검사가 실제로 잡는지 확인한다. 0건이 "검사를 안 해서" 나온 것이 아님을 이렇게만 확인할 수 있다

플레이스홀더를 그대로 정규식에 넣은 grep 도 이 단계에서 드러난다 — 항상 0건이 나와 통과로 오독된다.

## 5. 중복 검출

```bash
python3 scripts/check_duplication.py
```

파일 사이에 같은 내용이 반복되는 구간을 찾는다.

중복이 발견되면 **어느 쪽이 단일 소스인지 정하고** 나머지는 참조로 바꾼다.
"A 가 단일 소스다" 라고 적어 두고 내용을 복사해 둔 경우가 가장 흔하다 — 그 복사본은 반드시 원본과 어긋난다.

## 6. 판정과 정리

기계로 잡을 수 없는 부분이다. 판정 기준은 [judgment.md](references/judgment.md) 를 읽는다.

- 설명인가 지침인가
- 애초에 하지 않을 일을 금지하고 있는가
- 모델이 판단해도 되는 것을 규정하고 있는가

## 7. 관심사별 커밋

유형이 다른 변경을 한 커밋에 담지 않는다.

- 사실 오류 수정
- 참조 갱신
- 중복 제거
- 설명 제거

커밋 메시지에는 **무엇이 어떻게 틀렸는지**를 남긴다. 같은 오류가 다시 들어오는 것을 막는다.

## 하지 않을 것

- **사용자가 이미 편집한 파일을 되돌리지 않는다.** 손상으로 보여도 먼저 확인한다. 포매터 손상과 사용자 편집이 섞여 있으면 손상만 골라 고친다
- **문서를 통째로 덮어쓰지 않는다.** 경계를 잘못 잡으면 의도하지 않은 구간이 사라진다. 섹션 삭제는 다음 헤더까지로 범위를 잡고, 삭제 전후 헤더 목록을 비교한다
- **자기 산출물을 스스로 승인하지 않는다.** 정리를 마치면 별도 에이전트에게 리뷰를 맡긴다. 리뷰 결과도 실측으로 걸러야 한다 — 서브에이전트도 틀린다
